### Diagnosis and disposition

The **checker is stale**, rather than this result demonstrating a missing
clock unwind. At `scripts/check-mpp-hardening.py:84`, its slice starts at
`static int rkvenc_clk_on(` and ends at `rkvenc_clk_off(`. At line 96 it demands
`goto err_core` followed by `clk_disable_unprepare(enc->hclk_info.clk)` within
that slice. But the implementation is now in
`drivers/video/rockchip/mpp/mpp_rkvenc2.c:2821–2847`,
`rkvenc_clk_on_unlocked()`, **before** the selected slice. The wrapper at
`:2850–2863` calls that helper at `:2858` and returns its result. The helper
enables aclk, hclk and core in order, and its `err_core`/`err_hclk` labels at
`:2842–2845` unwind hclk and aclk on partial failure.

Reported before any edit; **no checker or driver fix was made**. A separate
checker-maintenance change should cover the helper and retain mutation tests.
The existing repository gate remains **red**; this verification neither waives
it nor claims silicon clock-fault qualification. The parent comparison settles
causal attribution for this RGA commit, independently of that future repair.

The serious-looking message is exactly:

```text
rga_mm.c:4334:6-12: ERROR: reference preceded by free on line 4336
```

Within one iteration, `n = import->count` precedes `kfree(import)`. Across
iterations, `rga_mm_session_release_buffer()` reacquires `mm->lock`, clears
`buffer`, and assigns `import = rga_mm_lookup_import(buffer, session)` at
`:4324` before reaching the count read again. If no import is found, the
`:4329–4331` guard exits. The freed import was removed from `buffer->import_list`
at `:4335`; `rga_mm_lookup_import()` (`:1562–1571`) only returns an entry still
in that list. `rga_mm_refresh_diagnostic_owner()` (`:1636–1648`) likewise uses
the remaining list rather than the freed local. Thus the reported
free-to-dereference path cannot retain that freed import. This disposition is
specific to this diagnostic, not a general lifetime approval of the driver.
